# AI Infra Quant：参考 R20 的产品化方案与后续 Codex 提示词

编写日期：2026-09-07  
状态：独立规划草案；未修改 GitHub、工作分支、当前任务合同或实现文件。  
用途：让当前 Codex 任务继续完成，在其复核与集成之后改写后续任务。

## 1. 建议采用的产品目标

把 AI Infra Quant 做成具备 R20 完整操作体验的个人量化决策工作台：美港股行情、自选矩阵、K 线与结构标注、PAQS-E 分析、历史决策、策略工作室、模型配置、模拟组合、研究复盘，以及必要的本地维护工具。

R20 可作为功能和界面的参考工程，也可提供经审查的可复用代码。现有项目继续提供行情、策略、账本和安全边界。PAQS-E 仍是默认主策略；当前市场仍是已经验证支持的 US/HK 标的。真实交易由用户在券商官方客户端完成。

“参考 R20”应形成可操作、可验收的用户流程，不能只更换配色；也不代表把 OKX 合约交易、杠杆、自动执行、原始策略参数和已发现的安全缺陷一起导入。

## 5. 前端技术路线

R20 当前是 Vue/TypeScript/Pinia/Vue Router 体系，其 `TacticalChart.vue` 实际使用 `klinecharts`。本项目当前是普通 HTML/JS/CSS + 本地 vendored Lightweight Charts。复制 `.vue` 文件并不能直接得到可运行页面。

推荐首个 007C 保留当前前端技术栈，复用已验证的数据刷新、图表和 Windows 启动路径，提取 R20 的视觉与交互实现。前端代码可以适度模块化，但不同时更换后端、数据库和图表库。

如果在具体复用清单中证明大批 Vue 组件经过适配仍可节省工作，再通过独立前端迁移任务采用 Vue/Vite：构建产物仍由本地 FastAPI 提供，浏览器只访问本地 API，用户启动时不依赖公网 CDN。Node 构建需求和 Windows 安装路径必须明确。迁移不应反向迫使后端改成 R20 的 `/api/all`、3 秒全量轮询或币圈数据结构。

## 7. TASK-007C 应如何改写

建议名称：**TASK-007C — PAQS-E Decision Workbench, R20-Inspired UX**。

这是下一份合同的完整范围建议，不是已签发合同。正式编写时，基线必须是 007B 实际通过复核并集成后的 SHA。

### 7.1 用户界面与流程

- 顶部：产品身份、当前市场/标的、行情时间、数据健康、刷新状态；不把 Phase 1 开账种子数展示成实时券商资产。
- 左侧：可增删的 US/HK 自选列表，当前选中状态、行情及数据可用性；避免不受控制的逐标的历史查询。全表实时扫描不是本任务。
- 中部：当前行情图与快照证据视图。保留 Daily/1m 的现有功能；按 007B 已持久化的快照证据展示 W1/D1/M30，历史决策查看时明确进入历史快照视图。007B 合同第 6 节要求保存完整的有界 W1/D1/M30 bars；007C 必须验证实际读取的证据包含这些数据，否则显示证据不可用，不用重新下载的数据冒充当时快照。
- 右侧：独立的模型选择、已注册策略选择及 Analyze 按钮；分析结果按“结论 → 结构与位置 → 触发条件 → 失效与目标 → 不确定性”呈现。
- 历史区：当前标的成功 Decision revisions 及详情；如接口允许显示失败 Analysis Run，则按真实失败状态呈现。失败不能伪装成成功的 NO_TRADE。
- 详情区：完整已校验结构化输出、快照 As-Of、模型/策略/提示词/验证器身份、证据和哈希。高级审计字段默认折叠。
- 用词：Holder Advisory 是“若持有时的条件建议”，不能暗示应用知道真实仓位。

### 7.2 API 与状态规则

- 首先核对 007B 实际合并后的 OpenAPI 和读写契约，不根据草案臆造已存在的响应字段。
- Analyze v1 请求仍为 `security_id / model_id / strategy_id`，使用服务器控制的 runtime/prompt，辅助上下文为空。
- 可以增加有界的只读模型/注册策略元数据接口，但不得在 007C 引入 provider 管理、密钥编辑或任意策略上传。
- 一个有效点击只发出一次 POST。处理中禁用重复提交；明确手工再次 Analyze 才是新的推理尝试和 revision。
- 浏览器超时/网络中断不自动重试 POST，因为服务端可能已经完成持久化。提示“结果未知，请查看历史后再决定是否重新分析”。主动关闭请求不等于取消服务端运行。
- 用户切换标的后，旧请求的结果不能覆盖新标的视图；完成的结果仍应在其原标的历史中可查。
- 行情约 60 秒刷新、切换周期、打开历史、窗口重新可见均不触发 PAQS-E 分析。
- 最新行情时间和 Decision 的 snapshot As-Of 分开展示。行情更新不会移动历史失效位、目标或改变旧结果。
- 图表和前端不重新计算策略门槛、不改写 advisory；缺数据明确显示，不生成替代行情。
- 策略只有一个注册版本时，仍显示它的身份，不能伪造多个可选策略或可用模型。

## 8. 策略工作室与模拟盘需要另外写清楚的内容

### 策略工作室

必须正式扩展当前仅从 registry/filesystem 读取的运行策略权威边界。草稿编辑不意味着立即生效；启用时生成新注册版本、身份与内容哈希，所有后续 Analyze 明确绑定该版本。历史运行证据仍不可修改。

复制 R20 的模块排序、变量插入、完整预览、方案复制、历史差异和导入导出交互。导入为声明式受限数据，不接受任意文件路径、Python 或 shell。PAQS-E 核心基线、规则权限及证据纪律不能被普通 prompt 开关关闭；需要改变策略语义时，使用独立候选策略和评估记录。

### 模拟组合

必须拥有独立的 PaperFill 与模拟账本，不能在 PAQS-E Decision 上增加执行状态并把“建议”当成“已成交”。关联 `decision_id` 仅用于研究归因。

合同需要定义：成交时点和价格来源、用户确认、数量与最小单位、币种、费用、模拟现金约束、撤销/更正方式、外部资金流、NAV/收益、缺价及缺汇率处理。HKD/USD 不得无汇率直接相加；暂时不支持 FX 时按币种分别显示。现有开账单位化基础应复用，不能另算一套互相矛盾的收益。
